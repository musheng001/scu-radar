# 川大雷达 · 案头

面向个人使用的四川大学公开信息情报台。当前已接入国关、教务、学工、研招、就业、文学院、哲学系、古典学系、商学院及北大/人大/清华/复旦部分公开栏目；竞赛栏目单独保留全量历史线索。人工补录与收藏仅保存在当前浏览器。

## 已完成

- 简报入口改为 `secretary-brief.html`：支持本地直接打开、手机排版、折叠课表及诊断；每次原有构建会同步生成 HTML、Markdown 和 JSON。本轮没有新增或调整定时任务。
- `study-context.json` 保存经本地原件核对的 13 门课程、特殊周次、英语和新中国史考核要求及规则摘要。详见 `本地课程与规则盘点.md`；个人材料保持本地使用，公开部署前需拆分私有部分。

- 从四川大学官网的机关部处、院系和业务单位目录自动生成 `scu-channel-catalog.json` / `scu-channels.js`；本次刷新收录 115 个去重后的官方渠道（目录变化时数量会随之变化），并在首页“全校渠道”中支持搜索。目录刷新失败时保留上次成功版本。
- 课程基础设施已纳入渠道目录：个人课表、开课信息、教室查询、校历、教学作息、大川学堂、学习通和爱课堂。个人本学期课表属于登录后数据，只在用户本人完成教务登录后读取，不保存密码、不代替选退课。
- 首页内置三套完整视觉版本，右上角直接切换：`风骨`（米白宋体、编辑部式）、`夜航`（深蓝黑、低照度）、`清简`（白底无衬线、现代卡片）。三版共用同一份数据与功能，不复制业务代码。
- 将原先重复出现的来源按钮、来源筛选和来源健康长表收束为“一处筛选 + 一处诊断”；卡片摘要默认只显示两行，需要时再展开。
- 首页优先区只放仍可行动或确实需要人工核对的条目；活动回顾、已举办讲座和标题中日期已过的通告保留在全量资料库，不再挤占行动区。
- 将国关学院现有公开数据转换为网页可直接读取的 `radar-data.js`。
- 默认按行动价值、窗口期、个人方向相关性和发布时间排序。
- 区分仍可行动、待核、已截止和历史资料，不把关键词命中直接当成机会。
- 显示来源健康状态、生成时间、条目数量和自动化模式。
- 每次构建同时生成 `secretary-brief.md` / `secretary-brief.json`，把行动事项、竞赛、来源异常和登录入口整理成秘书简报；它不保存邮件令牌，也不执行邮件发送。
- 秘书简报的个人排序档案与展示上限在 `secretary-config.json`；它只影响优先查看顺序，不会从雷达全量数据中删除竞赛或来源记录。
- 保留搜索、分类、收藏、手工补录及个人数据导入导出。
- 提供增量更新：平时只读取各栏目的最新页，每七天自动做一次完整扫描。
- 竞赛按“全部公开竞赛先收录、相关性只用于排序”处理；本地验收批次发现 428 条教务处竞赛详情链接，定时更新会对该栏目最多回溯 60 个列表页/600 条详情线索，避免只盯第一页。
- 竞赛平台另有只读公开接口适配器 `collect_competition_api.py`：可用已保存样本离线验收，或在确认网络可用后按页抓取目录元数据；不会携带令牌，也不会调用报名接口。实时抓取默认关闭，避免把未经核验的目录项误当成报名通知。
- 登录门户、教务系统和公众号只登记入口/官方依据，不保存账号、密码，也不绕过登录、验证码或访问校验。

## 立即刷新

每天的统一入口是 `py daily_pipeline.py`：它负责增量抓取、保留上次成功快照、原子重建 `radar-data.js`、生成秘书简报，并把每次结果写入 `logs/pipeline.jsonl`。强制全量扫描使用 `py daily_pipeline.py --full`。若只需根据已经采集的数据重新生成网页资产，运行 `py update_radar.py --build-only`。如果电脑没有把 `py`/`python` 加入 PATH，直接运行下面的 `run_update_now.ps1` 包装脚本即可；它会自动选择系统 Python 或当前 Codex bundled Python。

核心管道至少检查国关学院、教务处、教务处竞赛栏目和四川大学主站校园活动。校团委官网实测返回访问校验页，采集器不会绕过；校团委公开活动暂由四川大学主站校园活动栏目承接，直接入口仍作为阻断来源保留。

每日管道还会运行 `discover_scu_channels.py`，以四川大学官方组织机构目录为准刷新全校渠道索引。渠道目录表示“发现并登记”，不表示所有站点都已经通过正文解析验收；是否已接入抓取仍以网页的“来源诊断”和 `sources.json` 为准。

安装前可先做不写系统的检查：`powershell -ExecutionPolicy Bypass -File .\install_scheduler.ps1 -DryRun`；已安装任务的只读状态检查：`powershell -ExecutionPolicy Bypass -File .\check_scheduler.ps1`。需要立即刷新时，可运行 `powershell -ExecutionPolicy Bypass -File .\run_update_now.ps1 --build-only`。

竞赛平台适配器的离线验收命令：

```powershell
python collect_competition_api.py --fixture external-data\scu-contests\public-api-sample.json
```

确认公开接口稳定后，再手动运行 `python collect_competition_api.py --pages 11 --page-size 6`；这一步仍不登录、不报名，只保存目录元数据和官方详情链接。

## 安装本地自动更新

在 PowerShell 中运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\install_scheduler.ps1
```

Windows 计划任务版本每天 07:30 执行；电脑关机时不会运行，重新开机后会补跑。若 Windows 返回“拒绝访问”，可以改用 Codex 本地自动化承载同一个 `daily_pipeline.py`。该任务只访问公开网页，不读取账号、QQ、微信或个人教务数据。

## 个人云端

页面已经接入 Supabase 适配层：收藏、人工提交和个人资料可同步到云端；未配置时自动退回本地离线模式。建表、RLS 权限和浏览器配置步骤见 `SUPABASE_SETUP.md`。前端只允许填写 publishable key，禁止使用 `service_role`。

## GPT 录入进展

首页现在支持用自然语言登记学习进展：GPT 会把一段话整理成“已完成 / 下一步 / 备注”，页面先显示草稿，只有点击“确认写入简报”才会保存。确认后的记录写入本机 `progress-log.json`，并同步重建 `secretary-brief.html` 的“最近进展”版块。

这项功能必须通过本机服务使用，不能直接双击 `index.html`。先按 `GPT_SETUP.md` 设置用户环境变量 `OPENAI_API_KEY`，再双击 `启动川大雷达.cmd`。API 密钥只由 Python 服务读取，不会进入浏览器、JavaScript、进展文件或仓库。服务默认只监听 `127.0.0.1:8767`。

## 数据边界

- 登录类系统只做快捷入口，不保存密码。
- 公众号和群聊信息暂时通过人工补录进入。
- 网页上的“相关度”是排序辅助，不是对综测、推免加分或报名资格的认定。
- 采取行动前必须核对官方原文。
- 逐站运行结果、失败原因和覆盖范围见 `接入验收.md`；竞赛与公众号登记见 `private-channels.json` 和来源数据目录。
